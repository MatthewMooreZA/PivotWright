# Excel-written reference samples

All files were saved by desktop Excel 365 (Windows, en-ZA) from models first generated by this library, unless noted. Use `tools/python/extract_tree.py` to unpack.

| File | What it is |
|---|---|
| `S1x_excel_base.xlsx`, `S6x_excel_base_3tables_2rel.xlsx` | Excel re-saves of generated models with relationships and sort columns, no hierarchies |
| `S1xe_...`, `S6xe_excel_after_adding_hierarchy.xlsx` | the same after Create Hierarchy in Excel: the ground truth for the hierarchy version profile (SPEC §5.2) |
| `V2b_pivotwright_hierarchies_verified.xlsx` | generated by PivotWright, verified in Excel; the base for H1–H3 |
| `H1_hidden_columns.xlsx` | V2b with columns hidden from client tools in Excel |
| `H2_date_table.xlsx` | V2b with Dates marked as a date table |
| `H3_date_table_and_hidden.xlsx` | both |
| `H5_sort_reapplied.xlsx` | `datetbl_gen_ye2_v1` (February year end) after Sort by Column was re-applied to FiscalQuarter in Excel: shows StructureType Unnatural for the Fiscal Calendar hierarchy (SPEC §7) |
| `H8_hide_one_column.xlsx` | V2b with only Sales[Qty] hidden: the counters after one hide operation on a plain column (SPEC §8) |
| `H9_hide_one_hierarchy_level.xlsx` | V2b with only Products[Product], a hierarchy level, hidden (SPEC §8) |
| `H8e_hide_one_column_with_edits.xlsx`, `H9e_hide_one_hierarchy_level_with_edits.xlsx` | H8 and H9 after further edits in Excel (a second hierarchy, more hidden columns): Excel can edit its own hidden-column files, which our generated equivalents could not (SPEC §8) |

| `H6_calculated_column.xlsx` | `calcbase_v1` (the standard Products/Dates/Sales model) with Sales[Line Total] `=[Qty]*[Amount]` added in Power Pivot: the ground truth for calculated columns |
| `H7_calculated_column_related.xlsx` | the same base with `=RELATED(Products[Category])` added to Sales; the column kept Excel's default name "Calculated Column 1" |
| `H10_calculated_column_manual.xlsx` | `calcbase_v1` with Sales[Line Total] `=[Qty]*[Amount]` added in Manual Calculation Mode and not calculated: the on-disk shape of an unprocessed calculated column (formula only, no values) |
| `H11_calc_wholenumber_manual.xlsx` ... `H15_calc_text_manual.xlsx` | `calcbase_v1` plus one unprocessed calculated column of each type on Sales, in manual calculation mode, type left on auto: H11 `[Qty]*2` (Whole Number), H12 `[Qty]/2` (Decimal), H13 `[Date]+1` (Date), H14 `[Qty]>2` (TRUE/FALSE), H15 `"Qty "&[Qty]` (Text). Each was renamed after it was added, so the column id is "Calculated Column 1"; their counters differ from H10 and from each other (different edit histories), so only the per-type column content was taken from them (SPEC section 10) |
| `H18_calc_two_on_sales_manual.xlsx`, `H19_calc_on_products_manual.xlsx`, `H20_calc_sales_and_products_manual.xlsx` | `calcbase_v1` in manual mode with: H18 two columns on Sales (`Line Total`, then `Double Qty`); H19 one column on Products (`LEN([Product])`); H20 one on Sales (`Line Total`) then one on Products. The counters for several columns (SPEC section 10); the columns kept the id "Calculated Column 1" (and "Calculated Column 11") |
| `H21_plain_calc_on_sales_manual.xlsx`, `H22_plain_calc_two_on_sales_manual.xlsx`, `H23_plain_calc_on_products_manual.xlsx`, `H24_plain_calc_sales_and_products_manual.xlsx` | the same four shapes as H10/H18/H19/H20 on `calcplain_base_v1`, the standard model **without hierarchies** (`datagen ... plain`); manual mode was set in each session (it is not remembered); the counters for models without a hierarchy (SPEC section 10) |
| `H25_calc_three_on_sales_manual.xlsx`, `H26_calc_four_on_sales_manual.xlsx`, `H27_calc_two_sales_one_products_manual.xlsx`, `H28_plain_calc_three_on_sales_manual.xlsx` | three and four columns on Sales and two on Sales plus one on Products (on `calcbase_v1`), and three on Sales on `calcplain_base_v1`; the counters keep growing in straight lines (SPEC section 10) |
| `H29_date_calc_on_sales_manual.xlsx`, `H30_date_calc_two_on_sales_manual.xlsx`, `H31_date_calc_on_dates_manual.xlsx`, `H32_date_calc_sales_and_dates_manual.xlsx` | calculated columns in the hierarchy model with Dates marked as the date table (`calcdate_base_v1`, `datagen ... date`): one and two columns on Sales, one on Dates, one on each (SPEC section 10) |
| `H31B_date_calc_on_dates_manual_with_hierarchy.xlsx` | H31 plus a hierarchy `Year > Year Month` on Dates, made while the column was uncalculated: Excel keeps that hierarchy unprocessed (SPEC section 10) |
