# PivotWright 0.1.0-preview.3

Draft, not yet published. Compared with `0.1.0-preview.2` (2026-10-20). A preview: the API can still change before 0.1.0, and every breaking change is listed here.

## Highlights

- **Calculated columns.** `table.AddCalculatedColumn(name, dax, dataType)` stores a DAX formula and no values. Excel calculates the column; the library never evaluates DAX. Works with every column type (text, whole number, decimal, currency, date, true/false), `RELATED`, hidden columns, hierarchies over a calculated column, `SortByColumn` between calculated columns, many columns on one table, columns on the one-side table and on the date table, several fact tables, and tables of more than one segment.
- **Calculate on open.** Excel calculates a calculated column only on demand, so by default it could be used as a PivotTable value but not as a row, column or filter until it had been calculated once. `DataModelOptions.CalculateOnOpen` (default true) fixes that: a model with a calculated column gets a hidden one-row linked table and a very hidden worksheet, and Excel calculates every calculated column when the workbook opens. No macro, no password prompt, nothing in the field list. Excel asks the usual Enable Editing and Enable Content questions for the workbook's data connections.
- **Formats.** Number and date formats for measures, data columns and calculated columns, as in Power Pivot's Format command. Currency with a chosen symbol or none, culture-driven dates, and date formats given as **.NET date format strings**.
- **Generated date table.** `AddDateTable` gains `DateTableOptions.DateFormat`.

## Breaking changes

1. **API redesign (object model).** Operations moved onto the object they change: `sales.AddMeasure(...)`, `products.AddHierarchy(...)`, `dates.MarkAsDateTable(...)`, `sales["ProductKey"].IsHidden = true`, `column.SortByColumn = other`, `model.AddRelationship(manyColumn, oneColumn)`. `TableWriter` is now `ModelTable`; `DataModelOptions.Lcid` is now `DataModelOptions.Culture`; `model.TableNames`, `DateTableName` and the `*Count` properties are replaced by the `Tables`, `DateTable`, `Relationships`, `Measures` and `Hierarchies` collections. `AddTable` returns the table, not a row count. Unknown names in `model.Tables["X"]` and `table["X"]` throw `KeyNotFoundException`. Every change is a compile error at the old call site, so nothing changes silently. The full mapping is in `docs/API-USABILITY-REVIEW.md` ("Migration from 0.1.0-preview.2"). The output bytes of existing models are unchanged by the redesign.
2. **`MeasureFormat.Date` is now a method.** It was a static property; use `MeasureFormat.ShortDate()` (the culture's short date) or `MeasureFormat.Date("dd MMM yyyy")` (any .NET date format string, optional culture). `MeasureFormat.Currency` gains an optional culture.
3. **Models with a calculated column now contain an extra hidden table** (`CalculateOnOpen`, see above): a table `PivotWrightTrigger` in the model and a very hidden `Sheet2`. Set `CalculateOnOpen = false` to write only the formulas as before. A user table named `PivotWrightTrigger` is rejected at `Save` when the option is on.

## New API

- `ModelTable.AddCalculatedColumn(name, dax, dataType, format = null)`, `ModelTable.CalculatedColumns`; `ModelCalculatedColumn` (`Name`, `Expression`, `DataType`, `IsHidden`, `SortByColumn`).
- `ModelTable.AddHierarchy` accepts a calculated column as a level; `ModelHierarchy.LevelNames`, `IsUnprocessed`.
- `MeasureFormat`: `Currency(decimals, culture)`, `CurrencyWithoutSymbol(decimals)`, `ShortDate(culture)`, `LongDate(culture)`, `Date(format, culture)`. `ColumnDefinition.Format` and the `format` argument of `AddMeasure` / `AddCalculatedColumn`.
- `DateTableOptions.DateFormat`.
- `DataModelOptions.CalculateOnOpen` (default true) and `DataModelOptions.ExcludeSourceFromRefreshAll` (default false; leaves the placeholder data source out of Refresh All so it no longer asks for a password; Refresh All then refreshes the PivotTables only).
- Calculated column formulas are checked for paired brackets, parentheses, braces and quotes at the call (`ArgumentException`); the DAX itself is not parsed.

## Behaviour notes

- **Date formats are .NET format strings.** `Date("h:mm tt")`, `Date("yyyy-MM-dd HH:mm")`, or a single standard specifier (`"d"`, `"D"`, `"t"`, `"T"`, `"f"`, `"F"`, `"g"`, `"G"`, `"M"`, `"Y"`, `"s"`, `"u"`, `"R"`) that is expanded through the culture, so the order of day, month and year is never fixed by the library (`"d"` is `M/d/yyyy` for en-US, `dd/MM/yyyy` for en-GB). Patterns with a time zone (`o`, `K`, `z`) are rejected because the Data Model has none. A date format on a measure is limited to the model culture's short date.
- **Types are checked.** A number format on a text, true/false or date column, or a date format on a non-date column, is rejected at the call.
- Calculated columns need at least one relationship and at least one row in their table; `Save` lists the supported shapes otherwise.

## Excel verification

Every feature above was tested by hand in desktop Excel (generated files and Excel-written samples `H6` to `H46` in `reference/excel-samples/`): the model loads, values and formats display, hierarchies, Sort by Column, hiding, save and PivotTable refresh work. Calculate on open was checked on models with and without hierarchies, with a date table, two fact tables, a hidden data column, a hidden calculated column, a calculated column on the one-side table, eight columns of different types, and 1,100,000 rows. Not tested: Excel versions other than the owner's desktop Excel, Excel for the web, and Excel for Mac.

## Known limitations

- Formulas are not evaluated or validated by the library; a well-formed but wrong formula shows an error value in Excel.
- With `CalculateOnOpen = false`, an uncalculated column works as a PivotTable value but not as a row, column or filter until a field has been put in Values once (any field) or Calculate Now has been used. *Refresh All* does not calculate it. Details and the research behind the trigger: `docs/research-refresh.md`.
- Refresh All still asks for credentials by default, because the model's data source is a placeholder (set `ExcludeSourceFromRefreshAll` to avoid the prompt).
- Calculated column shapes that were never seen in an Excel-written file (for example a column on a table with no relationship) are refused with an explanation.
- Macro-enabled workbooks (`.xlsm`) are not written.
