## Highlights

- **Perspectives.** `model.AddPerspective("Sales view")` creates a perspective like Power Pivot's *Advanced > Perspectives*: a named subset of the model's columns, measures and hierarchies. Choose what it shows with `Include(column)`, `Include(measure)`, `Include(hierarchy)` or `Include(table)` (a whole table, like ticking the table in Excel's dialog: every column, every visible measure, every hierarchy). Any number of perspectives; Excel lists them in the Perspectives dialog and they can be edited there.

```csharp
var view = model.AddPerspective("Sales view");
view.Include(sales["Qty"]).Include(sales["Amount"]).Include(total).Include(products.Hierarchies[0]);
model.AddPerspective("Products").Include(products);
```

## New API

- `DataModelWriter.AddPerspective(string name)` and `DataModelWriter.Perspectives` (`ModelCollection<ModelPerspective>`, found by name, ignoring case).
- `ModelPerspective`: `Name`, `Columns`, `Measures`, `Hierarchies`, and the four `Include` overloads, which return the perspective so calls chain. Including something twice does nothing.
- A name must not contain `\ / : * ? " < > |` or control characters, must not start or end with a space, must not be "Model", and must be unique ignoring case (`ArgumentException`).

## Behaviour notes

- **Excel's rules, not ours.** A perspective that ticks a hierarchy does not show the hierarchy's level columns; include them as well to show them on their own. Excel stores a ticked hierarchy only in a cube annotation, never in the perspective file.
- **Models without perspectives are written exactly as before.**
- **No perspective can be chosen for a PivotTable.** Excel offers no way to pick a perspective for a PivotTable on the workbook's own data model (Microsoft documents perspectives as a data source only for workbooks on SharePoint with Excel Services). The library therefore writes perspectives into the model only. `docs/experiments/pivot-perspective.md` records an experiment (a hand-written PivotTable whose field list is trimmed to a perspective loads and offers only that subset); it is not part of the package.

## Excel verification

Written from three Excel-made samples (`H64`, `H65`, `H66` in `reference/excel-samples/`). A generated file with the three perspectives of H65 (`datagen ... persp3`) was tested by hand in desktop Excel: it loads without a repair message, the Perspectives dialog shows all three with the ticks that were made, editing a perspective works, and adding a hierarchy, adding a Sort by Column, saving and a PivotTable refresh all work. Differences from Excel's own files: the order of attributes inside a perspective and of the perspective list follows the model rather than Excel's order (which follows no rule seen); the files are sets, so this is not expected to matter. The shapes of H64 (`persp1`) and H66 (`perspH`) were not sent as generated files. Not tested: Excel versions other than the owner's desktop Excel, Excel for the web, and Excel for Mac.

## Known limitations

`Save` refuses, with a message that says what is missing, the shapes no Excel sample shows:
- a model without a hierarchy, without a relationship, or without a measure of your own;
- a model with a date table, hidden columns, calculated columns or KPIs;
- a perspective that shows nothing;
- two hierarchies of one table in one perspective (the separator Excel uses is unknown).

Each of these needs an Excel-written sample before it can be supported.
