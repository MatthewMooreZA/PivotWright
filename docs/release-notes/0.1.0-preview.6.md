# PivotWright 0.1.0-preview.6

Not yet published: drafted 2026-11-15 from branch `claude/modest-clarke-ecx91j` (47 commits on top of `main` at `682f5da`, the state of `0.1.0-preview.5`). Compared with `0.1.0-preview.5` (2026-11-01). A preview: the API can still change before 0.1.0.

## Highlights

- **Inactive relationships (role-playing dates).** A second relationship between two tables, such as a ship date next to an order date, is added with `isActive: false` after the active one, exactly as Power Pivot makes it when you drag a second column onto the date table. A measure uses it with `USERELATIONSHIP`.

```csharp
model.AddRelationship(sales["ProductKey"], products["ProductKey"]);
model.AddRelationship(sales["Date"], dates["Date"]);                                        // active: filters Sales by order date
var shipped = model.AddRelationship(sales["Ship Date"], dates["Date"], isActive: false);    // shipped.IsActive == false
sales.AddMeasure("Qty by Ship Date", "CALCULATE(SUM(Sales[Qty]), USERELATIONSHIP(Sales[Ship Date], Dates[Date]))");
```

- **Re-save rule corrected.** Excel saves the *first table of the model* again after a KPI, a perspective or a calculated column is added (and after a column is hidden). The library had assumed the primary side of the first relationship, which was the same table in every layout seen until now. Models whose first table is not that table (for example tables created in the order Dates, Products, Sales, or the date relationship added before the product one) are now written the way Excel writes them (`H86` to `H93` in `reference/excel-samples/`). Models in the usual layout are written as before.

## New API

- `DataModelWriter.AddRelationship(ModelColumn many, ModelColumn one, bool isActive = true)`. Two tables have one active relationship; a further one must be passed `isActive: false` and needs an active one between the same two tables with the same many side.
- `ModelRelationship.IsActive`.

## Behaviour notes

- **Errors.** A second relationship between two tables without `isActive: false` still throws `ArgumentException`; the message now says to pass `isActive: false`. A second relationship between the same two columns, and an inactive relationship without an active one beside it, are refused with messages that say what to do.
- **Inactive relationships are stored like active ones** (dimension relationship, relationship table and index) but have no entry in the workbook's relationship list and no measure group dimension, which is how Excel marks them. Next to calculated columns Excel left the new relationship unprocessed (manual calculation mode) and the library writes it that way; `CalculateOnOpen` (the default) makes Excel process it when the file opens.
- **Generated files are written to match Excel's samples**, so every shape below has an Excel-written sample behind it.

## Excel verification

Each shape was written from an Excel-made sample (`H73` to `H85` in `reference/excel-samples/`) and then tested by hand in desktop Excel as a generated file: loads without a repair message, Diagram View shows the dotted line, a `USERELATIONSHIP` measure gives its own values, adding a hierarchy and a Sort by Column work, and saving works.

- One inactive relationship: with hierarchies (`H73`), with a date table (`H76`), in a model without hierarchies (`H79`), with hidden columns (`H80`), with only the hidden helper measure (`H81`), next to a calculated column (`H82`), a KPI (`H83`) or a perspective (`H84`); with the date relationship added first (`H78`).
- Two inactive relationships in one table (`H77`), and one in each of two fact tables (`H85`).
- Three inactive relationships in one table, and two with a date table: written by the same formulas, no Excel-written sample, tested by hand as generated files.
- Re-save rule: KPIs (`H86`, `H87`, `H90`, `H91`), perspectives (`H88`, `H89`), calculated columns (`H92`, `H93`). Generated files for these layouts were compared with Excel's files; they were not all sent to Excel as generated files.

Not tested: Excel versions other than the owner's desktop Excel, Excel for the web, and Excel for Mac.

## Known limitations

`Save` refuses, with a message that says what is missing, the shapes no Excel sample shows:
- inactive relationships from more than two tables, or several in each of two tables;
- an inactive relationship in a model with hidden columns but no hierarchies or with a date table; with a KPI and a date table, hidden or calculated columns, or no hierarchies; with calculated columns on another table than its many side, or several inactive relationships together with calculated columns or perspectives;
- an inactive relationship whose many-side table has no other active relationship to a different table (Excel's samples all had one).

Not understood: when two fact tables each have an inactive relationship Excel saved the second fact table again and not `Products` (`H85`); the library follows that sample. A model whose first table is a fact table is unverified for the re-save rule, and a hide still does not write the first-table save (SPEC section 8).

Each of these needs an Excel-written sample before it can be supported.
